# Zenith

A two-player dueling card game. Great houses vie for the king's favor through structured duels; each sends a named spellsword fighter. Design: `../designs/zenith.md`.

- **Engine:** Godot 4.6 (Forward Plus), GDScript
- **Status:** playable hotseat and online prototype. Rules engine with headless tests, 3D playspace, deck select, six starter decks whose cards carry their full mechanics (functional names, no flavor yet).
- **Run:** Open `zenith/project.godot` in Godot 4.6 and press F5. Title → Hotseat duel → pick two decks → play. The table swings to whoever has to decide, behind a hand-off screen.
- **Against the AI:** Title → Duel the AI → pick your house and the AI's, and Easy, Normal or Hard in the footer. You sit at seat 1 and the AI's hand stays face down.
- **Online:** one player presses Host online duel (port 7777), the other types the host's address and presses Join. The select screen becomes the lobby: each client picks its own house, the host starts. The host runs the rules; the joiner receives only what its seat may see and sits at its own side of the table.

## Engine

`DuelEngine` runs the duel as a state machine. It advances on its own until a player has to decide something, then exposes a `Prompt` whose `options` are the only `Command`s it accepts. `submit(command)` applies one and runs on to the next prompt or the end of the game. Everything that happens is appended to `events` as `GameEvent`s for the client to animate and log. Same seed plus same commands replays the same game.

```gdscript
var engine: DuelEngine = DuelEngine.new()
engine.setup([deck_a, deck_b], library, strike_table, seed_value)
engine.start()
while not engine.is_over():
	var choice: Command = engine.prompt.options[0]   # a driver picks here
	engine.submit(choice)
```

Prompt kinds: `armory` (armory_in / armory_done), `non_combat` (place / master / done), `declare` (declare / skip), `attack_action` (attack, with value `"empower"` for the Empowered version / use / power / copied_attack / final_strike / pass), `respond` (counter / decline), `defense` (defend / power_defend / no_defense), `control` (context `role` attacker or defender), `redirect` (target), `endurance` (endure / no_endure), `capture_instead` (capture / deal_damage, for an attacking Ally with the capture trait), `critical` (capture / discard_ally / lower_acclaim / no_critical), `keep` (keep / discard_all), `recover` (recover / no_recover), `pay` (value = Vigor paid), `discard_choice`, `pick_in_play` (+ pick_none), `name_card` (value = title), `pick_option`. A prompt raised by a card's effect carries `source` (the card's uid) and `card_title` in its context, and a `pick_option` also says what the pick is for (`purpose`: forbid_type, stop_kind, look_at, capture), so titles name the card asking and the client can show it.

Batches: a prompt that picks several cards (`armory`, a discard of two or more, a search or pick-in-play for several) also sets `batch_type`, `batch_min`, `batch_max` on the `Prompt` and `PromptView`. One Command of that type with `value` = an Array of card uids taken from the options answers it in a single step; `Prompt.accept` normalises and checks it, and the referee refuses anything outside the options, repeats, or the wrong count. Clients build it with `PromptView.batch_option(uids)`. The one-card options stay legal, so drivers that pick one at a time still work.

Effects run through a queue that pauses on a choice prompt and resumes afterwards, so a card can ask its owner or the target to pick cards mid-resolution.

A hand Combat card is an attack-phase `use` only when playing it does something (it has secondary effects). A pure counter ("use when needed", `counter: "combat"`) is offered only in the `respond` window that opens when the other player uses or defends with a Combat card; in its owner's own attack phase it can only be thrown away for a Final Strike.

**Log.** Every state change is an event with a line from `CardText.event_line`, so the log tells the whole story and not only the players' commands: a card whose trigger fires gets "<card> triggers when entering Combat" (once, at the first effect that actually applies, never for a card the player just played or used), every Vigor change from an effect names its source card and the before and after, forbids and other standing effects read as they land ("may not perform Arts for the rest of Combat"), flags such as a skipped attack phase or a forced Combat are announced when set, and wounds outside an attack's own damage, removals from the game, looks at the deck and bonds each have a line. Lines are worded per seat (`event_line(ev, engine, seat)`): a card is named only if that seat may see it now or is the player who acted, so the opponent of a draw check learns whether it matched and that the effect follows, never which card was drawn, and an Armory swap or a search into hand reads "a card" on the other side.

**Seat views.** Clients never read the engine. `Referee` owns it and answers each seat with a `SeatUpdate`: the log lines for what happened, a `SeatView` (public standings, every zone as uids, and a card table where cards that seat may not see carry only uid and zone: Life Decks, the other seat's hand and Armory), and a `PromptView` when the next decision is that seat's (kind, title, options with ready-made labels). `Referee.submit(seat, command)` refuses anything that is not the pending prompt's own option from the right seat. Everything has `to_dict` / `from_dict` so the same objects cross the wire. Card uids are dealt after the shuffle so a face-down uid says nothing about the card.

**Attack in the air.** `SeatView.attack` carries the public shape of the current attack plus `damage`, the breakdown from `DuelEngine.damage_breakdown`: the Strike Table lookup (both Mights and bands, or the Art base, or printed numbers), then `adds`, one entry per card that changes it (Drills, Mastery, Grounds, attachments, floating modifiers, Empower, paid Vigor), and the totals. Before the defense it is the forecast the defender is answering; once `landed` is set the battle sequence has fixed the same numbers, and `stages_dealt`, `life_dealt` and `life_remaining` follow the flips. The HUD prompt panel shows it under the attack chip for every prompt the attack opens, on both seats, and the log gets a "Strike Table: Might 19 (C) vs 9 (B) gives 2 stages." line and a "Modifiers: +4 stages (Relentless Fury). Total 8 stages." line per attack. A Final Strike is a legal option on every hand card, so the client never fires it from a bare card click: it sits behind a "Final Strike…" button that opens the hand in the tray, and a card whose only action is a Final Strike opens the sub-choice tray instead of committing.

**Outcome.** `SeatView.battle_step` says where the battle sequence stands while an attack is in the air, and `SeatView.last_attack` keeps the outcome of the last attack of the Combat after the attack itself has left the view: who attacked, with what (`source_title`, `performer_title`), whether it was stopped and by what (`stopped_by` is `{card, how}` with `how` card / power / shield / floating, `stopped_by_title` the wording), `stages_dealt`, `life_dealt`, `target_title`, `endurance_prevented`, and the critical-damage choice. It clears when the next attack is declared or Combat ends. The log gets the same tally as one line at `attack_end` ("Bram's Overhand Cut lands for 3 stages, 2 wounds." / "… is stopped by Tide Parry."), a "Combat: Bram attacks first." line at `combat_begin`, and a line when a defense is skipped for a reason the player should know (no legal defense, or a Final Strike this Combat).

**Attack forecasts.** While a seat's attack action is pending, `SeatView.forecasts` (only that seat's view) carries a breakdown per offered attack, keyed by the option's card uid: hand and Remain cards, a Power attack under the personality's uid, and a bare Final Strike for a card with no attack of its own (`is_final`). `DuelEngine.attack_forecasts` builds each one the way declaring it would (`_build_attack`: the card's conditional lines, the attacker's standing effects) and runs the same `_damage_calc`, after paying the attack's Vigor cost so the Strike Table is read at the right stage (`cost_stages` travels with it); an Empower option adds its totals under `empowered`. The hand shows each card's total as a chip ("6 Vigor", "4 wounds"; "Final: 2 Vigor" in grey for a card that can only be thrown away), and the quick view lists the steps under the face, so a "+3 Vigor" card is compared by what it would land for, not its printed bonus. Faces carry the printed base in a badge over the art ("Strike +3 Vigor", "Strike Table Vigor", "Art 4 wounds", "Focused Strike 7 Vigor"), from `CardText.attack_badge`. `CardText.breakdown_steps` is the one wording for a breakdown's steps (prompt panel and quick view alike).

**Event data for animation.** `SeatUpdate.lines` entries carry `type`, `player` and the seat's `line`; for the event types in `Referee.ANIMATED` they also carry `data` with only the public fields listed there (card uids that reached a pile, damage numbers, the attack's kind and source), the same for both seats. Anything not listed reaches clients as its line alone, so nothing hidden leaks through the animation channel.

**Effective values.** A `SeatPlayer` carries every per-player number the rules currently apply, computed by `DuelEngine` getters (`acclaim_needed`, `acclaim_gain`, `recover_gain`, `acclaim_shield`, `tier_shield`, `restrictions`) from base state plus standing effects: a Mastery that demands 6 Acclaim of its opponent, a forbid in force. Clients render those fields and never a rules constant, so a card that moves one moves the display in the same update. `PlayerState.acclaim_needed` is the adjustable base behind the first of these (ops `acclaim_needed` and `set_acclaim_needed`); the opponent's Mastery demand is layered on top, the higher wins.

Covered: Armory swap at setup, bracket first-player rule, 7-step turn, 6-phase Combat, 15-step battle sequence, Strike Table, Arts with costs and cost discounts, overflow to wounds, Endurance (fixed and X), Defense Shields, Focused and unstoppable attacks, unpreventable damage, prevent-all, floating stop-all and stop-next, Acclaim and Favor tiers (set, lose, advance, threshold changes, Acclaim and tier shields), Allies (placement, overlay, control at any stage, redirect, protection), Drills with guild lock, modifiers, shields, once-per-Combat uses and Drill protection, Tokens (placement, bypass, capture, capture effects, both win paths), Grounds with standing forbids, Masteries (modifiers, entering-Combat, on-success, use), Masters with per-game powers and passives, Final Strike, Remain, Empower, counter window for Combat cards, attack variants ("if X is in control, +3"), per-Ally and Surge-scaled damage, pay-any-Vigor attacks, attachments (modifiers, entering-Combat draws, wound removal), constant powers (focused attacks, first styled attack unstoppable, on-attack, turn-start, shared with Allies), named-card locks, copied attacks, forbids by card type / attack type / powers / Mastery / Drills / end-Combat / stop-all / Tokens / everything-but-attacking, searches by type, guild, title, tag, signature, or Armory into hand or play, start-in-play Drills, hand discards chosen by either player or shuffled back.

Also covered: "you may" prompts on any effect line with a `then` list that runs only on a yes, pay-any-Vigor effects with a per-unit follow-up, look-at-top-or-bottom-N with a pick, searches that let the searcher choose among distinct hits, instead-of-damage choices after a successful attack, attacks that need two stops, Ally powers usable without control, Drills that promote "if successful" text or discard themselves, Remain cards that shuffle back when unused, returning removed cards, forbids with a Vigor escape clause, forced Combat declarations.

And: Bonds (two named Allies fold under a Bond card that fights as one at full Vigor, burning a life card each turn until it ends), wound triggers on life cards ("if this card is discarded from your Life Deck…", optionally delayed to the next fight-back phase), look-at with a play-instead option and reshuffle, searches by what a card does (`has_effect`), an end-turn effect, and a response window during the opponent's Declare step (`opponent_declare` trigger on a Non-Combat in play).

Also: damage multipliers (one at most, the biggest applies) and caps on modifiers (`multiply`, `cap_stages`, `cap_life`; caps bite at deal time), attacks that cannot be reduced (`no_reduce` on the attack, or a floating `no_reduce`), Tokens immune to card effects that do not name them, cards that end Combat usable only as an attack action, "X only" attachments that go on X wherever X stands (`attach` with `to: "character"`, playable while X is in play; `to: "named"` with `character` attaches to a different named personality, needs X in control and the named one on the table, and `attachment.limit_attached` caps copies per host), an unplayable drawn guild Drill shown and shuffled back (`shuffle_back` option in the Non-Combat step), and look-at effects that put the looked-at cards back in a chosen order (`rearrange: true`).

Timing windows, audited against the reference rulebook and rulings on 2026-09-16: a spent Fighter (Vigor 0 or 1) may hand the attack phase to an Ally at the start of it (`control` prompt with `role: attacker`), and resumes control once above that; a Non-Combat in play used as a defense is spent; after a Final Strike the player cannot defend either (Shields and standing stops still apply); a skipped attack phase never happened, so the passes around it are not consecutive; a Master's power is offered where its `master_step` says (`non_combat`, the default, `combat` for in place of an attack, or `any`); an attacking Ally with the capture trait may capture a Token instead of dealing damage (battle step 11); the Recover step is announced every turn (`recover_step` event) and the card returns only when Combat was skipped.

Not yet: Use-when-needed windows outside the Combat-card counter and the Declare window (no starter card needs one), choosing the order of Defense Shields, of "if successful" effects, or of one's own entering-Combat effects (they resolve in printed or source order), the free Ally takeover when the opponent uses a non-attack card, trying an any-type stop against a Focused attack for its secondary effects, the replacement effects the design lists (draw from the discard pile, keep cards in the Discard step, alternative costs, blank text boxes), and Restricted Drills. A card with both an attack and a utility mode can only attack; no starter card has one.

## AI

One AI plays every deck. Nothing in `ai/` names a card or a deck; it reads card data and table state.

- **`AiProfile`** is the data: weights for the AI's own side (`own`), the opponent's (`foe`), effect ops (`effect`), play costs (`play`), and how hard it thinks (`think`: `search`, `top_k`, `samples`, `budget_ms`, `max_steps`, `noise`, `prior`). Defaults live in `AiProfile.DEFAULTS`; a JSON file under `data/ai/profiles/` overrides only what it lists. A deck's playstyle is a profile: raise `own.token` for a Token deck, `own.favor` for a Favor deck, `own.ally` for an Ally deck.
- **`AiEvaluator.evaluate(engine, seat, profile)`** scores a position. Each win route is its own term: Life Decks (survival), Acclaim and tiers (Favor), Tokens of one set (Token win), plus Vigor, Might band, hand, Allies, Drills, Non-Combats, attachments and forbids. The opponent's side is scored with `foe` weights, so a beatdown AI still fears six Tokens.
- **Grounds** bind both players, so `AiEvaluator.grounds_value` scores them by whose cards they help and hinder: the AI's whole deck against what the opponent has shown in play, discard and removed piles. It reads the Grounds' data (forbids, doubled costs, modifiers, searches), never their id. The evaluator counts the Grounds in play, and the scorer rates placing new Grounds as new minus old, less the Combat that placing them gives up (`play.grounds_skip`). Weights: `own.grounds`, `foe.grounds`.
- **`AiScorer`** scores each option of the pending prompt with no simulation, from `attack_forecasts`, `damage_breakdown` and effect ops. It is the Easy AI, the move ordering for the search, and the policy both seats follow inside a playout. An option type it does not know scores 0, the same as "do nothing".
- **`AiSearch`** is the lookahead. For each of the scorer's top `top_k` options (plus one "do nothing" option) it asks for a simulated engine, plays the option, lets the scorer play both seats until the turn ends, and evaluates. It averages over `samples` deals and stops at `budget_ms`. Every option meets the same deals. `last_report` lists what it weighed.
- **`AiPlayer.choose(referee, seat)`** returns the wire form of one of the prompt's options, or `{}` when the decision is not that seat's.
- **Fair play.** The AI never holds the real engine. `Referee.sim_for(seat, sample_seed)` returns `DuelEngine.clone()` after `determinize(seat, seed)`: every card the seat cannot see trades identity at random with the owner's other hidden cards, and the random stream is replaced. The seat's `SeatView` of the simulation equals its view of the real duel; a test checks that. The AI does not yet remember cards it saw earlier (a searched card, a revealed hand).
- **Cost.** A clone plus determinize is about 1.5 ms, a submit about 0.25 ms. Normal averages about 100 ms per decision with a 400 ms cap. In the client the search runs on a `WorkerThreadPool` task so tweens keep playing.

## Client

- `duel_view.gd` renders one seat's `SeatView` and nothing else. Hotseat and hosting keep a `Referee` in the scene; after every command it plays the seat's `SeatUpdate` into the log and into table tweens, then shows the next prompt. A `Card3D` exists per uid the view lists, with a face only when the view carries a definition. Any card decision can be made by clicking the card (in the 2D hand or on the table) or by the button list in the prompt panel, which always lists every legal option.
- Combat beats: `_play_update` replays each event line that carries `data` as its own beat (`_replay`) against the update's final layout before the closing sync. An attack raises its card to the Play slot, lunges the attacker's personality at the defender's with a streak and sparks (`duel_fx.gd`, the `Fx` node: floating text, bursts, slashes, rings, all primitive meshes freed when their tween ends), and shows a banner (`DuelHud.toast`) naming it; a defense rings the defender in blue; "Hits for 8 Vigor, 1 wound" banners the total; a Vigor hit shakes and flashes the target with "-5 Vigor" over it; each flipped life card arcs from the Life Deck to the discard face up (`_fly`) with "Wound N"; Endurance, Token capture, tier changes, Vigor and Acclaim changes all get their number over the card. Discards and removals arc to their pile as their event plays instead of sliding in the sync. While an attack is in the air the two personalities in control carry a role glow under the card (attacker red, defender blue, `Card3D.set_role`; `Body` under the card holds the quads so shakes and lunges never fight the table tween). `Engine.time_scale` (`--dev-fast`) speeds every beat.
- `table_layout.gd` turns zone names into table slots. Each zone owns its own rectangle on the felt (two rows per side: Mastery, Allies, Fighter, Tokens, Life Deck, Discard; then Master with its Armory, Drills, the card in play, Non-Combats, Removed; Grounds across the centre). The outlines and labels on the table are drawn from the same markers and slot counts. Rows squeeze past their slot count instead of spilling into a neighbour. Player 1's slots mirror player 0's; every card and label turns to read upright for the current viewer.
- `card_face_cache.gd` draws each card face once into a `SubViewport` and caches the texture. Faces are procedural (`card_face.tscn`, 512 x 716) in two layouts. Fighters and Allies get a portrait: tier box and name across the top, art down the left, the ten-stage Might ladder down the right with the Surge badge under it, and the tier's power text along the bottom. Every other card gets title, type chip, an art box of a fixed height for its type (`CardFace.ART_HEIGHTS`: 320 px for Strikes, Arts and Tokens, 300 for Combat, 240 for Non-Combats, Drills and Grounds, 220 for Masteries, 200 for Masters), a Vigor cost badge over the art, the rules text in the fixed box that remains, and Endurance under it. Boxes never move between cards of one type; the text steps its font down from 24 to 12 px to fit. Art comes from `assets/card_art/<id>.png` when it exists, covered and cropped to the box.
- Rules text comes from `CardText` in the engine (`rules_text` for cards, `tier_text` for a personality tier with its Power, Constant powers and Defense Shield). Effects that share a trigger and condition fold into one sentence; a forbid or board clear that hits both players reads once. `CardText.KEYWORDS` lists every keyword with a regex, a colour role and a tooltip; `scripts/ui/keyword_text.gd` turns plain text into BBCode with those colours (ink on the cream face, light on the dark HUD) and `keyword_label.gd` is the `RichTextLabel` that shows the tooltip on hover. Shorthand on the face: `Hit:` is "if the attack is successful", `Remain N` is "stays in play for N more uses this Combat"; each is a keyword with its own tooltip. Hovering any card (hand, tray, or table) shows a quick view of its face at about half size beside the pointer; it follows the mouse and never takes clicks. Right-click any card or press Inspect in a card's action choice to bring it up in the centre at full size over a dimmed table; that face is live, so hovering a keyword on it explains it. Esc or a click outside closes it.
- The table camera (`table_camera.gd` on the duel scene's Camera) moves without changing its angle: the mouse wheel dollies toward the spot under the pointer, middle-drag or WASD / arrow keys pan along the table, and the look point is kept on the table by a margin that grows with height, so a zoomed-out view stays centred while a close view can roam to the edges. After four seconds without any input it glides back to the home framing; hand-offs and the hotseat swing send it home at once. Key panning is ignored while a text field has focus.
- Fighter numbers live on the fighter card, not in the HUD. `status_markers.gd` sits under each personality `Card3D`: a pulsing bar over the Might ladder rung for the current Vigor stage (one step below the ladder, in the warning colour, at 0), and one Acclaim pip per point the fighter currently needs along its top edge (the row is rebuilt when `acclaim_needed` changes). Rung positions come from the face layout (`CardFace.ladder_rects`, cached by `CardFaceCache`). The player panels show only seat data: Life Deck, hand, discard, removed, Armory, Tokens, and standing flags, including any effective value that differs from the printed rules ("Needs 6 Acclaim", "Acclaim shielded", "No Art attacks"). The quick view and the inspect view are live faces fed the same state through `SeatView.live_vigor(uid)` and `SeatView.fighter_owner(uid)`, so a personality in play shows its lit rung, its Acclaim pips and its live Recover gain in the Surge badge there too (`CardFace.show_def(def, tier, vigor, standing)`); cached table textures carry none.
- Dev panel (debug builds, hotseat and host only): the Dev button beside the phase strip opens a panel of effect buttons (Acclaim, Vigor, tier, draw, wounds, recover, discard, end Combat or turn, and a search by title into hand or play) for the viewer or the rival. Each runs as an engine effect through `Referee.dev` and `DuelEngine.dev_effect`, so triggers fire as they would from a card; the engine then re-issues the pending decision. Refused while a card effect is mid-resolution (choice prompts). Every use is logged as a Dev line.
- The log strip at the top right has a More/Less button that drops it down to most of the screen height; `--dev-log` opens it for screenshots.
- Hotseat: when the prompt's player changes, a hand-off overlay hides the hand, and on confirm the camera swings to that player's side.
- Online: the host (seat 0) runs the only `Referee`. The joiner holds no engine and no seed: it sends its choices up as `Command` dictionaries and gets back seat 1's `SeatUpdate`, so hidden cards never reach its process. Traffic that arrives while the table is still animating waits in a queue. When the other player is deciding, the prompt panel says so without listing their options. Disconnects end the duel with a notice; only the host can call a rematch or return both clients to the lobby.
- What the host can still do: read everything, since the rules run in its process. That is the friends-only limit of P2P; a headless server running the same `Referee` for both seats is the next step, and the client already speaks only views.

Dev flags after `--` when launching `res://scenes/duel/duel.tscn` directly: `--dev-autoplay` (random legal choices), `--dev-steps=N`, `--dev-seed=N`, `--dev-stop-at=<prompt kind>` (stop autoplay at the first prompt of that kind, e.g. `defense`, or `kind:flag` such as `pick_option:may` for prompts whose context sets that flag; add `--dev-click` to open the first hand card's action sub-choice before the shot, the way a real click would, or `--dev-click=final` for the first card whose only action is a Final Strike, or `--dev-zoom` to open the inspect view on the first hand card, `--dev-zoom=fighter` for the viewer's fighter, `--dev-zoom=rival` for the other fighter, `--dev-peek` or `--dev-peek=fighter` for the quick view, `--dev-log` for the dropped-down log), `--dev-pick=A,B` (deck indexes, in file order, for the two players), `--dev-ai` or `--dev-ai=hard` (seat 2 is played by the AI with that profile; autoplay then answers only for seat 1; the select screen takes `--dev-ai` too), `--dev-policy=attack` (autoplay declares Combat, attacks whenever it can and never defends, so a short run shows damage and a fight back; `--dev-stop-at=attack_action:fight_back` then lands on the defender's answer), `--dev-freeze=<event type>` (take the screenshot in the middle of that event's combat beat, with its effects still in the air: `attack_declared` for the swing and banner, `damage_stages` for the hit, `life_card_flipped` for a wound), `--dev-fast` (tweens run at eight times speed, so a long autoplay takes seconds), `--dev-camera=dx,dz,notches` (pan the table camera by dx right and dz ahead in table units, then zoom that many wheel notches toward the screen centre, before the shot), `--dev-hide-hud`, `--dev-screenshot=<path.png>`. The select screen takes `--dev-pick=A,B`, `--dev-tier=N` (show player 1's fighter at tier N, as portrait clicks would) and `--dev-screenshot=<path.png>`. On the select screen, clicking the chosen fighter's portrait cycles through the tiers the deck plays with, lowest first and wrapping, with the caption and the lit row in the tier list saying which face is up.

Online without clicks, launching the project (title scene) twice: the first instance with `--dev-host`, the second with `--dev-join=127.0.0.1`; both with `--dev-pick=A,B` (each uses only its own seat), `--dev-autoplay` (the host starts as soon as both seats are set), `--dev-steps=N` (counts every command applied, so both stop on the same state) and `--dev-screenshot=<png>`. Online, `--dev-seed` and `--dev-pick` on the duel scene are ignored because the lobby already agreed on both.

## Loadouts

Six starter decks modelled card-for-card on a community set of sample decks for the reference game, ordered easy to advanced. Counts and roles are kept and each card carries the mechanics of the card it stands in for, written in the effect schema below; every name is original. `data/cards/starter/starter_set.json` and the deck files are generated together by `tools/gen_starters.py` (run it from `zenith/`), so edit the generator rather than the JSON by hand.

Alignment strings are `knight` and `knave` (the Chivalry and the Knavery at court; see the design doc's Setting). Knights open the duel when the bracket rule does not decide it.

Later rulings adopted with them: the Armory swap happens as a prompt before the first turn, and the first player is decided by Strike Table bracket instead of doubling stages.

Structural rules from the 2014 relaunch, adopted 2026-09-16: every deck carries a Mastery and that Mastery's guild is the deck's Style (nothing is declared, the old +1 Surge stays as a flat bonus for every deck, Endurance always works); the Favor win is full Acclaim at the fighter's own top tier; an attack that deals 5 or more life cards is critical damage and the attacker may capture a Token, discard an Ally, or lower the rival's Acclaim by 1, ignoring Ally and Acclaim protections since it is a game rule and not a card effect; Fighter Powers are once per turn and a tier change mid-Combat does not refresh them. Nothing else from the relaunch is adopted: deck sizes stay 50 to 85, Fighters keep 3 to 5 tiers, Surge and Might stay per fighter.

Remaining approximations in the starter set:

- Hard Glare and Challenge show the owner the opponent's whole hand as the choice list. Tokens 2, 6 and 7 of each set are simple fillers the sheets never use.
- Truce ends the turn for both players: nobody takes a Discard step.
- Bonds (the two-Allies-as-one card): the Bond burns one life card per turn of its owner and ends at five; the two Allies return at 3 Vigor and the Bond card goes back to the Armory. A Bond that leaves play takes both Allies with it.

## Card JSON

```json
{"id": "ember_overhand_cut", "title": "Ember Overhand Cut", "type": "strike", "guild": "ember",
 "endurance": 1,
 "attack": {"kind": "strike", "stages": 2},
 "effects": [{"trigger": "if_successful", "op": "acclaim", "amount": 1}]}
```

- `type`: fighter, ally, strike, art, combat, non_combat, drill, token, grounds, mastery, master
- `guild`: ember, tide, storm, shade, steel, root, or omitted for Freestyle
- `attack`: `kind` strike | art; `stages`, `life` add to base; `printed_stages`, `printed_life` replace it; `cost_stages` (default 2 for arts), `cost_life`; `focused`, `unstoppable`, `no_prevent`, `no_stop_by` (a card type), `stages_from_table`, `life_per_ally`, `life_from_surge`, `only_first_attack`, `pay_stages` `{per, life}`, `variants[]` of `{when, ...overrides, effects}` merged when the condition holds
- `defense`: `{"stops": "strike" | "art" | "any"}` plus optional `when` (condition), `stop_all` (kind), `stop_focused` (true or `"discard_hand"`), `cost_stages`, `cost_life`, `copy_attack`. A card with both `attack` and `defense` attacks in the attack phase and defends in the defense phase; `use_in_attack` lets a pure defense also be used in place of an attack
- `effects[]`: `trigger` secondary (default) | if_successful | if_stopped | before_damage (after a successful attack, before damage; with `skip_damage` the attack then deals none) | on_place (a Token's trigger-less lines count as on_place: they resolve as it enters play, and a captor may run them on capture) | use | master_use | on_success (Mastery) | entering_combat (optional `role`) | on_wound (this card left the Life Deck as a wound or cost; `at: "fight_back"` delays it to the next fight-back phase of the Combat) | opponent_declare (a Non-Combat in play, offered to its owner during the opponent's Declare step); `who` self | opponent; `when` (condition); `may` asks the owner first; `then` is a list of effects that run right after this one (only on a yes for `may`, once per unit paid for pay_vigor); `after_empower` drops the line when Empowered. Ops: acclaim, set_acclaim, vigor (amount or `"max"`, `target` fighter, `no_overflow`), set_vigor, draw, draw_until, draw_discard (`from`), draw_check (guild, effects), discard_life, discard_hand (`random`, `chooser` owner, `to` deck, `filter` signature | non_token), remove_hand, pay_vigor (`per`, with `then`), look_at (`from` top | bottom, `amount`, `pick` filter, `to`, `play_if` filter for a card that may go into play instead, `shuffle_after`), search (`card_type`, `guild`, `title_contains`, `exclude_title`, `tag`, `signature_of` fighter, `source` deck | discard | either | armory, `to` hand | play, `stages`, `amount`, `has_effect` `{op, who}` to match by what a card does; the searcher picks when several distinct cards match, `choose: false` takes the first), choose_forbid_type (`unless_vigor_min`), return_removed (`card_type`), focus_attack (the current attack becomes Focused), end_turn, force_declare, bond (`card`: the Bond Ally id, found anywhere in the owner's zones), discard_in_play (`card_type` non_combat | non_combat_only | drill | freestyle_drill | ally | token | non_combat_or_ally | drill_or_ally, `amount`, `all`, `remove`, `choose`, `up_to`, `chooser`), remove_discard (`all`), shuffle_discard (`per_personality`), recover, end_combat, skip_next_attack_phase, cannot_declare_combat, stop_all, choose_stop_all_kind, float (`what`, `duration` combat | turn | next_turn_end, `params`), forbid (`what`, `duration`), lose_tier, advance_tier, set_tier (`tier` or `"acclaim"`), no_favor_win, attach (`to`), capture_token, name_card, next_attack_tax
- Conditions (`when`): character, fighter_character, alignment, performed_by, tier_min, vigor_min, opponent_acclaim, allies_min, ally_present, opponent_allies_min, opponent_non_combats_min, discard_top_guild, discard_top_guild_not, discard_top2_guild, discard_min, higher_might, opponent_used_combat_card, first_attack, role, tokens_min, hand_min, stopped_last_phase, source_guild, attack_focused. A Mastery's `on_attack` effects are offered whenever its owner declares an attack, and its `blocks_to_bottom: <guild>` key sends a used block of that guild under the Life Deck when the block stopped the attack and does not remove itself
- `vigor` accepts `target` fighter | last_searched (the card the last search put into play); A `search` whose `source` is the deck (or `either`) is a look through the Life Deck: the searcher is always prompted, even with one match or none, the prompt's `library` context lists the whole deck by title and `SeatView` reveals those cards to the searcher alone, `pick_none` takes nothing, and the deck is shuffled once when the search ends (event `deck_shuffled`) unless the effect sets `no_shuffle`. A `look_at` shuffles only with `shuffle_after`. `draw_check` takes `check` guild | named | signature | title_contains, `discard: true` to check a life card thrown away instead of one drawn, and `else_effects` for a miss
- Floating `what`: no_prevent, prevent_all, make_focused (guild), after_use_bottom (guild), damage_removes, no_gain, no_ally_control, keep_hand, endurance_boost, no_endurance, stop_next, prevent_art_life, modifier (a modifier dict, `once` for a single attack)
- Forbid `what`: strike_attacks, art_attacks, strike_cards, art_cards, combat_cards, non_combats, drills, mastery, powers, end_combat, stop_all, tokens, non_attack_actions, skip_combat. Printed `forbid[]` lists work on Grounds, Drills, and Non-Combats
- `modifiers[]` on drills, masteries, grounds and constants: `scope` own | against, `kind` strike | art | any, `stages`, `life`, optional `guild`, `title_contains`, `when`, `per_ally`
- `forbid[]` on grounds and drills: `{"who": "all" | "owner" | "opponent", "what": ...}`; `shield` on drills: strike | art | any; `attachment`: `{target, modifiers, effects, damage_removes, title_contains}`
- Keywords: `endurance`, `endurance_when` `{value_if, then, else}`, `empower`, `remain`, `remain_when` `{when, remain}`, `unused_return` `"shuffle"`, `counter` `"combat"`, `start_in_play` (from the Life Deck or the Armory), `only` `{character | fighter_character}`, `bottom_after_use`, `remove_after_use`, `once_per_combat`, `tags[]`; on Drills also `promote_if_successful` (title fragment) and `discard_if_other_non_combats`
- Attack extras: `stops_needed` (the defender must stop it that many times), `life_per_opponent_token`
- Personalities: `character`, `tiers[]` with `tier`, `surge`, `might` (11 ints for stages 0 to 10), optional `wild`, `shield`, `power` (`attack`, `defense`, `effects`, `uses`, `no_control_needed` on Allies), `constant`; a Bond Ally adds `bond_of` (two Ally characters) and `bond_timer_max`, and can never be placed directly (`attacks_focused`, `first_styled_unstoppable`, `damage_removes`, `protect_allies`, `ally_control_any_stage`, `allies_share`, `acclaim_multiplier`, `forbid_opponent[]`, `modifiers[]`, `on_attack[]`, `turn_start[]`, `entering_combat[]`)
- Masteries: `art_cost_delta`, `opponent_tier_threshold`, `protect_drills`; Masters: `armory_size`, `uses_per_game`, `master_step` (`non_combat` by default, `combat`, `any`), `master_flags` (`no_favor_win`, `acclaim_shield`, `tier_shield`); Grounds: `double_costs`
- `text` overrides the generated rules text; `alignment_only`, `limit_per_deck`, `token_set`, `token_number`, `capture_trait`

Deck JSON: `name`, `fighter`, `tiers`, `style`, `alignment`, `mastery`, `master`, `armory[]`, `cards[]` of `{"id", "count"}`.

## Tests

```powershell
$godot = "G:\Godot\Godot_v4.6.2-stable_mono_win64\Godot_v4.6.2-stable_mono_win64_console.exe"
& $godot --headless --path zenith --import
& $godot --headless --path zenith -s tests/run_tests.gd
```

Run the import once after adding a `class_name` script, or headless runs will not see it. The suite also validates every deck in `data/decks/` and plays each one against itself with random choices to the end. `tests/stress_starters.gd` plays every deck pairing for three seeds and reports any game that does not finish.

`tests/ai_arena.gd` plays AI policies against each other over every deck pairing, from both seats, and prints win rates, win reasons, wins per deck and milliseconds per decision. Run it after any change to `ai/` or a profile:

```powershell
& $godot --headless --path zenith -s tests/ai_arena.gd -- --a=search --b=scorer --seeds=1 --budget=150
```

`tests/ai_trace.gd` plays one game (`--deck=`, `--foe=`, `--seed=`, `--budget=`) with the search AI in seat 0 and prints a line of table state per turn plus a tally of seat 0's commands and events, which shows whether a playstyle profile does what it says. `tests/print_text.gd -- <card ids>` prints generated rules text.

Policies are `random`, `scorer`, `search`, or a profile name (`easy`, `hard`). `--decks=a,b` limits the decks, `--samples=N` and `--budget=MS` override the profile, `--verbose` prints a line per game.

Visual check without a screen:

```powershell
& $godot --path zenith --resolution 1600x900 res://scenes/duel/duel.tscn -- --dev-autoplay --dev-steps=45 --dev-seed=5 --dev-screenshot=C:\path\shot.png

```

The suite's `test_seat_view_masks_hidden_cards` checks exactly which cards go out blank, `test_referee_gates_commands` that the wrong seat or a forged option is refused, `test_uids_hide_deck_order` that uids do not follow the deck list, and `test_command_wire_lockstep` that a second engine fed only wire-form commands ends in the same state.
