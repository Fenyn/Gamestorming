1.3.0 (unreleased)
- One install instead of two. The engine and the interface now ship as a single
  mod that turns on whichever half the machine needs, so single-player, co-op
  hosts, remote clients and dedicated servers all install the same thing. Remove
  the old PalPriorityUI mod before updating: the mod refuses to start while it is
  still installed rather than let two copies fight over the same pals.
- Fixed: a high-output station could bring hauling to a standstill. Once a base
  produced items faster than its pals could carry them away, every item in the
  growing pile cost the mod work every second, on the same thread the pals think
  on — so the backlog starved the pals that would have cleared it, and hauling
  collapsed instead of just falling behind. The mod now stops counting a pile
  past the point where the count could change any decision. Priorities behave
  exactly as before; a base that is simply short of haulers still puts every
  available pal on hauling, which is the correct answer to a real backlog.
- Fixed: a pal at a base with nothing left to do could stay stuck on one job type
  forever. A base only announces itself to the mod when it has UNFINISHED work, so
  a base that was fully caught up became invisible and its pals were never
  reconsidered — including pals left restricted from before a restart.
- Fixed: a pal could permanently lose one of its priorities. A single failed read
  while checking what a pal is capable of was enough for the mod to conclude it
  could no longer do that work, and to delete the setting from disk. It never came
  back, and the pal quietly stopped doing that job for good.
- Fixed: clicking a work checkbox from an unmodded client could leave a pal
  restricted with no settings left to un-restrict it. The mod now only hands a pal
  back to vanilla when it can actually confirm the hand-back.
- Fixed: when the mod's attempt to RE-ENABLE a work type failed a few times, it
  stopped retrying for two minutes — so a retry limiter meant to prevent problems
  was itself leaving pals unable to work. It now only ever backs off disabling.
- Fixed: work the mod cannot identify (an unrecognised station) is no longer
  tracked without limit, which was the one gap left in the runaway-pile guard.
- Campfire and construction work: 1.2.0 fixed these only for the FIRST campfire or
  build site in a base. Every later one is now recognised too.
- Known gap: Oil Extraction has no recognised work behind it yet, so setting an oil
  priority currently does nothing. Being fixed for the next release.

1.2.0 (2026-07-25)
- Fixed stutter. The engine no longer scans the game's object list every tick or
  re-checks pals when nothing has changed.
- Pending work is counted per base. Jobs at one base no longer fence pals at
  another base that cannot reach them.
- Jobs are allocated down the priority list instead of fencing every pal onto the
  same job. Pals that miss out stay available for other work instead of idling.
- Fixed: campfire and construction work was invisible to the mod. A pal set to
  Kindling 1 / Ranching 5 stayed in the ranch while a campfire went cold.
- Fixed: item-pickup jobs were classified as hauling and hidden from pals set to
  Gathering.
- Fixed: the first click on a work cell cycled to the wrong value (3 went to 1,
  X went to 4).
- Fixed: pals could take the wrong job briefly after a base loaded.
- Fixed: a pal could be left with work permanently disabled if it was reset to
  vanilla while its managing player was offline.
- Fixed: on a co-op host the interface mod could attest another player's click as
  its own, cycling an unmodded player's vanilla checkbox.
- Fixed: priority numbers could persist on a pal reset while you were disconnected.
- Priority changes apply within about a second (previously three), and config
  writes are batched per burst of changes rather than per click.

1.1.0 (2026-07-17)
- Numbers now show immediately when the work screen opens: unconfigured pals
  display their default values (3 for enabled types, X for disabled) in a dim
  neutral color. Dim = vanilla defaults, display only; colored = managed by the
  priority engine. Clicking a cell activates the pal with exactly the values
  previewed.
- Priorities now survive server restarts and pal redeployment. The game quietly
  gives a base pal a new internal identity when it is re-instanced (restart, or
  picking it up and putting it back), which orphaned its priorities — they now
  migrate to the pal's new identity automatically, matched by a stable fingerprint
  (species + talent IVs + gender). Identical bred twins are the one case that
  cannot be told apart; those just need their priorities set again.
- Dedicated server and remote-client support. The server now syncs priorities to
  every modded player over the game's own replicated RPC channel, so PalPriorityUI
  no longer needs to be on the same machine as the server. Thanks to the testers
  in the comments for the sharp diagnosis of the old file-based design.
- Fixed: clicking a work column a pal cannot do no longer shows a priority number
  (the engine now checks work suitability before cycling — thanks for the report
  and the code pointer). Bogus entries from 1.0.0 are cleaned up automatically.
- Fixed: priority numbers could permanently disappear from a pal after longer
  sessions — the client could announce itself on the wrong network component, so
  the server mistook a modded click for an unmodded one and reset the pal to
  vanilla. The client now uses its own player component and re-announces
  periodically.
- Fixed: config file not found on the Steam Workshop UE4SS layout (thanks for the
  path fix in the comments).
- Much faster fallback to lower-priority work. When a pal's preferred job gets
  taken by someone else (or a work queue finishes), other pals now fall down
  their priority list within a few seconds instead of idling for 15-25 seconds.
- Stability: removed an unverified engine call used while identifying station
  jobs (crafting/production benches) — the prime suspect for the reported
  crashes that started once advanced production benches were built — and
  hardened all work-object handling against stale references. If 1.0.0 crashed
  for you, please retest on this version and report back.
- Internal mod versions now match the release version.

1.0.0 (2026-07-14)
- Initial release.
- Per-pal, per-work-type priorities replacing the vanilla work toggles.
  RimWorld scale: 1 = most important, 5 = least, X = never.
- Integrated UI on the Monitoring Stand work screen: color-coded values
  (green 1 -> yellow -> red 5), left/right-click to cycle.
- Priority engine with event-driven pending-work tracking (including station jobs:
  crafting, smelting, cooking, farming) and anti-flip-flop hysteresis.
- Multiplayer safety: unmodded clients stay fully vanilla; uninstalling the client
  mod gracefully returns pals to vanilla on/off on next interaction.
- Config persistence in the mod folder (no save-file writes); F8 reload, F9 diagnostics.
