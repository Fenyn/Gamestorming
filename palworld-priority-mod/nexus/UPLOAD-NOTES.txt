Nexus page setup notes
======================

CURRENT STATE: 1.2.0 is what is published (two files). 1.3.0 is built but not
uploaded, and it is ONE file. The "Files tab" section below still describes the
1.2.0 pair because that is what is live on the page right now — read the 1.3.0
notes at the bottom before uploading anything, because they replace it.

Page

Files tab (1.2.0, as currently published) — BOTH are Main Files, both required:
- PalPriority-1.2.0.zip    -> file name "PalPriority (logic — server/host)"
- PalPriorityUI-1.2.0.zip  -> file name "PalPriorityUI (interface — every player)"
Each is a single-component archive rooted at ue4ss/Mods/<Name>/ — this is the
layout the official Vortex Palworld extension parses (one tracked mod per
archive; enabled.txt is ignored by Vortex and used by manual installs).
The zips contain ONLY the ue4ss tree — no loose root files. A shared root
file (e.g. INSTALL.txt) in both archives deploys to the same path and makes
Vortex flag a mod conflict between the two files. Install instructions live
on the mod page instead (the release/ folder keeps INSTALL.txt for the
manually-shared friend bundle only).

Images: at least one required. Best shots:
- Work screen with numbers + X mix on a pal row (the money shot)
- A pal at its priority-5 station with the number UI visible in the corner

Before upload: run the verification pass — (1) single player: numbers
render, both click directions cycle, unsuitable columns stay blank when
clicked, console shows PrioSync lines, no HOOK FAILED lines; (2) co-op host
with a modded and an unmodded guest; (3) dedicated server: PalPriority on the
server only, remote modded client gets numbers on opening the work screen and
can cycle. No F-keys are active in release (F8/F9/F10 are all behind the
DEBUG flag at the top of each main.lua).

Zips: build with 7-Zip or python zipfile, NEVER the Windows built-in
compressor (it writes backslash entry paths that break on other OSes).

1.2.0 notes
- The core mod gained a second script: Scripts/planner.lua. It is required —
  main.lua does require("planner"). Anyone updating by hand must copy both.
- priorities.lua ships in the archive (as it has since 1.0.0), so a manual
  extract over an existing install overwrites a player's saved priorities.
  Mention "back up priorities.lua before updating" in the update description.
- Diagnostics ship off: DEBUG=false in both mods, VERBOSE=false in the core.
  Verified in the built archives.

1.3.0 notes — THESE SUPERSEDE THE "Files tab" AND "1.2.0 notes" SECTIONS ABOVE
- Single archive: the mod is now one folder containing both halves, gated at
  runtime on authority (engine) and local player (interface). The separate
  PalPriorityUI file is retired - mark it obsolete on the Nexus page.
- SIX scripts, all required, all hard require()d:
    main.lua  shared.lua  registry.lua  engine.lua  planner.lua  ui.lua
  Copy the whole Scripts/ directory. Naming files individually is how
  registry.lua got left out of the Workshop packaging list.
- Diagnostics ship off: DEBUG=false and VERBOSE=false, both at the top of the
  single main.lua (1.2.0 had a DEBUG flag in each of its two mods). Verify in
  the built archive.
- Players MUST remove the old PalPriorityUI mod. 1.3.0 detects it and refuses to
  start rather than run two engines against the same pals; the log says what to
  delete. Put this at the top of the update description.
- priorities.lua is no longer shipped in the archive. The engine creates it on
  first change and mirrors it to %LOCALAPPDATA%\Pal\Saved\, which is what
  stops a mod-manager deploy or a Workshop reinstall wiping saved priorities
  (observed live on a Vortex deploy 2026-07-25).
