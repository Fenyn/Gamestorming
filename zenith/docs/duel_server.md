# Duel server

Every online duel is refereed on the duel server. Run it from the editor binary with `--headless --path zenith -- --server --port=7777` or from the exported binary with `--headless -- --server --port=7777`; `--data-dir=<path>` and `--keep-days=N` place and age its match records (below), `--host-name=<name>` names its DTLS certificate (default `eidolarch`, Transport below) and `--no-dtls` runs it on plain ENet. Both players connect out to it, one opens a room and gets a five-letter share code and the other joins with the code, or both press Find a duel and the server pairs them (below), and the server runs that room's duel with the only rules engine (`scenes/server.tscn`, `scripts/server/duel_server.gd`, rooms in `Net`). Clients hold no hidden information and pick only from the options the server sends, so a modified client gains nothing. Because players connect out to a fixed address, nobody forwards ports and no NAT punchthrough or relay is needed.

The client reads the address from the project setting `zenith/net/duel_server` (`project.godot`, `[zenith]` section); `--dev-server=host:port` overrides it for one run. It reads the server's certificate from `zenith/net/duel_server_cert` (Transport below); `--dev-server-cert=<path>` overrides that.

## Same build on both ends

The server and every client must be built from the same commit. A connection opens with a greeting on the MultiplayerAPI's auth channel, before any RPC: the client sends `Net.PROTOCOL`, `Net.catalog_fingerprint()` (SHA-256 over every card file, the deck files in list order and the strike table, line endings ignored) and its identity ticket (below), and the server refuses a different protocol number or hash with a sentence the client shows on its title. The greeting does not depend on the RPC table, so two builds that disagree about RPCs still get the reason across. `Net.PROTOCOL` goes up whenever an RPC is added, removed or renamed, its arguments or their meaning change, or the room flow changes. A client that reaches a server too old to greet at all says "The duel server did not answer the greeting. It is probably running a different version of the game." The server's first log line prints its protocol and the first 12 characters of its catalog hash. The protocol is 10 since 2026-10-01 (deployed that day), was 9 since the online presentation pass (`_rpc_queue_state` gained its third argument, `ms`, and a match conceded as a whole ends `concede_match`), was 8 since ranked play (Ranked below: the ticket's `mode`, `_rpc_series`, `_rpc_game_over`, `_rpc_match_over`, `_rpc_rating`, `_rpc_next_ready`, `_rpc_leave_match`, and a match on one seat token), was 7 since identities and DTLS (the greeting's ticket, nonce and proof; `_rpc_queue_join` carries the identity), 6 since Find a duel (`_rpc_queue_join`, `_rpc_queue_state`, `_rpc_matched`, queue rooms), and 5 since reconnects. A server built before 7 runs plain ENet, which a client pinned to a certificate cannot reach at all: it reads as "Could not reach the duel server…". Export and deploy the server again (Update in one step), then export the clients, so they carry the certificate the new server made.

## Identity

Each install has one identity, so a later ranked mode has something stable to key ratings on (`scripts/net/identity.gd`, `Identity`).

- Key: an RSA 2048 key pair made with `Crypto` the first time a greeting needs it, stored as PEM in `user://identity.key` (`--dev-scratch=<dir>` moves it to `<dir>/identity.key`, so two dev clients on one machine are two identities). The private half is never sent, logged or put in a record. On Linux the file is set to owner read and write; on Windows the user profile's own access rules apply.
- Id: SHA-256 of the public key as PEM, 64 hex characters (`Identity.id()`). The server re-encodes the key it is sent before hashing it, so one key has one id however its PEM was spaced. The journal shows the first 12 characters (`Identity.short`).
- A missing key file makes a new identity and prints `identity: made a new identity <short id> in <path>`. A file that is there but cannot be read or parsed is renamed to `identity.key.bad-<unix time>`, never overwritten, and a new identity is made with a warning. If it cannot be moved either, that run uses a new identity it does not save, with a warning. A reinstall or a lost file is a new identity, so bans and ratings built on it stay soft.
- Greeting, in order, all on the auth channel before any RPC:
  1. Client to server: `{"protocol": 9, "catalog": <64 hex>, "ticket": {"kind": "key", "public": <public key PEM>}}`.
  2. Server to client: `{"nonce": <32 random bytes from Crypto>}`, or `{"refused": reason}` for a wrong protocol or catalog, or a ticket that is missing, of another kind or not a public key ("The greeting did not carry this copy of the game's key. …").
  3. Client to server: `{"proof": <signature>}`, RSA PKCS#1 v1.5 over the SHA-256 of the nonce, then `PROTOCOL` as 4 bytes little-endian, then the catalog hash as its 64 ASCII characters (`Net.challenge_bytes`).
  4. Server to client: `{"ok": 9}` and `complete_auth`, and the journal gets `peer P: identity <short id>, DTLS handshake done`. A wrong, missing or malformed signature gets `{"refused": "The duel server could not confirm this copy of the game's key. …"}`.
- This rides Godot's `SceneMultiplayer` auth callback, which carries any number of messages each way until both sides call `complete_auth`; the server calls it only after a good proof. The nonce is kept per connection (`Net._greeting`) and spent on the first proof that comes back for it, good or bad. A connection refused once gets no further answer, and an admitted one's further auth messages are ignored. A proof taken from one connection meets a new nonce on another.
- A client signs only for the duel server. A hosting client on the LAN dev path answers a good hello with `{"ok"}` at once and ignores the ticket, and a joiner never answers a nonce from one.
- The server keeps each admitted peer's identity (`Net._peer_identity`) until it disconnects, puts it on the seat it takes (`DuelRoom.seat_identity`, from a room request or a queue pairing) and into the match record's `seats[].identity`. An empty seat's identity is "", and an away seat keeps its own.
- Rejoin and give up: the token alone is not enough. The request must come from the identity that holds the seat, or it is refused with "That seat belongs to another copy of the game." (`_rpc_rejoin_failed`, final, so the client deletes its rejoin file). The give-up connection proves its key in its greeting like any other before the server reads its `give_up`.
- Queue: `_rpc_queue_join(ticket)` carries `{"identity": <id>}` (`Net.queue_ticket()`), plus `"mode": "ranked"` for the ranked queue. The server takes the identity from the greeting and refuses, with a journal line, a ticket that names another.
- One identity may hold several connections at once, and two seats of a casual or code room may share one. The ranked queue never pairs an identity with itself, and ratings and the leaver cooldown are keyed on the identity (Ranked below).

## Transport

The duel server's ENet host runs DTLS, so the rejoin token, the identity proof and every update are unreadable on the path, and a client talks only to the server whose certificate it pins.

- Server: on its first start it makes an RSA 2048 key and a self-signed certificate with `CN=<--host-name>` (default `eidolarch`, valid until 2049) into its data directory: `dtls.key` (private, 0600 under the unit's umask), `dtls.crt`, and `dtls.name`, the name the pair was made for, since a script cannot read a certificate's name back. Later starts load them. A start whose `--host-name` differs from `dtls.name`, or that finds only some of the three files or cannot read them, refuses to start with the reason, since a new pair would be refused by every shipped client; delete all three to make a new pair on purpose. It then calls `ENetConnection.dtls_server_setup(TLSOptions.server(key, cert))` right after `create_server` and logs `DTLS on, certificate <path> for <name>`. `--no-dtls` skips all of it and logs that identities and tokens travel in the clear.
- Client: the project setting `zenith/net/duel_server_cert` names the pinned certificate, `res://data/net/duel_server.crt` as shipped, which `deploy.ps1` fills. The client calls `dtls_client_setup(host, TLSOptions.client(cert, host))` right after `create_client`, with `host` the host part of the address it dials, so only that certificate is accepted and its name must be that address. The box's `--host-name` is therefore its public address, which `deploy.ps1` passes. For a check against a server on this machine, start it with `--host-name=127.0.0.1`.
- A setting naming a file that is not there, or not a certificate, stops the attempt at once with "This copy of the game is missing the duel server's certificate, so it cannot connect safely." An empty setting means plain ENet, which only a server started with `--no-dtls` answers.
- A wrong certificate: ENet does not say why a DTLS handshake failed, so the client runs a second DTLS handshake of its own beside the ENet one (`PacketPeerDTLS`, `Net._cert_probe`) and closes it once it has a verdict. A certificate that is not the pinned one, or whose name is not the dialled host, fails the attempt within a second with "The duel server's certificate is not the one this copy of the game trusts. It may be a different server, or this copy may be out of date." on the title. A server out of reach still reads "Could not reach the duel server…" after 10 seconds. Each refused handshake prints `TLS handshake error` on the server's stderr, so it shows in the journal.
- The give-up connection and a rejoin go over DTLS to the same pinned certificate.
- The LAN dev path (a client hosting on a plain ENet port, and a joiner typing its address) stays on plain ENet with no certificate, and has no identity check.

## Rooms

A room is in the lobby, in a duel, or over (`DuelRoom.Phase`).

- Lobby: each seat's pick is filed under the peer that sent it. Each client gets the room's lobby with the other seat's name and lock but no deck until both have locked. Both clients then show the matchup for three seconds and say so (`Net.ready_to_deal()`); the server deals once both have. Both decks are shown at that point, so from then on `_on_lobby_pick` refuses any change, a new deck, an unlock or a new name, and logs it; the matchup screen shows no Back in a server room. After a duel, Back to the lobby unlocks both seats and they pick again.
- A pick names a precon by its catalog index, or a player-built deck by `DuelRoom.CUSTOM_PICK` (-2) with the whole list in the entry's `list` (PROTOCOL 10). The authority rebuilds that list with `CustomDecks.from_wire` and accepts it only when it is tournament legal against its own cards and under `Net.DECK_LIST_MAX_BYTES`. The list stays hidden from the other seat until both have locked, then rides `_rpc_start` and `_rpc_resume` after the other deal arguments. A ranked room refuses a custom pick ("Ranked matches use the shipped decks only."), and the select screen does not offer custom decks there. The match record keeps a custom deck inline under `list` with an empty `deck` id.
- A player who leaves the lobby frees the seat, the other player stays with the same code, and a new player can take the seat. A room holding one player closes after 10 minutes (`--room-idle=N` seconds on the server) and tells that player why. A connected peer that never asks for a room is dropped after 20 seconds, and a peer refused a room cannot ask again on that connection.
- A player whose connection drops mid-duel keeps the seat for 90 seconds and can rejoin (Reconnects, below). A finished duel's room stays until both leave, a rematch starts, or a player takes both back to the lobby. Either seat can ask for a rematch; the other seat hears it, and the server deals again on the same picks with a fresh seed once both have asked. Either seat can concede during a duel; the server ends it with the other seat as winner and tells both. A seat whose clock runs out ends the duel the same way (below). The last player out closes the room.
- The server logs every room opening and closing with the code and the reason, every seat taken or left, lost connections and returns, rematches, returns to the lobby, concessions, clocks that ran out and refused messages.
- Rooms share nothing but the process. Every room's state lives on its `DuelRoom` (keyed by share code in `Net.rooms`) and its `DuelHost` (keyed by the same code in the server scene), every peer is filed under its room (`Net._peer_room`), and every message to a player goes through the room's own seat list. Share codes, seat colours, deal seeds and rejoin tokens all come from `Crypto`, so nothing one room is sent says anything about another. `network_regression_tests.gd` runs two rooms side by side and checks after every step that each peer gets only its own room's and seat's messages.

## Find a duel

The way into a duel without a share code. The client connects, passes the greeting and sends `_rpc_queue_join(ticket)` where a room request would go (`Net.find_duel()`). The server keeps one queue, oldest first (`MatchQueue`, `scripts/server/match_queue.gd`, RefCounted and pure, the clock passed into every call).

- Accepted: from a peer past the greeting that is not waiting already and holds no room in the lobby or a duel. `ticket` is a Dictionary, `{"identity": <id>}` from a client (Identity above); an identity other than the one the peer proved is refused and logged, and keys the server does not know are ignored. A peer whose duel is over leaves that room first, as if it had disconnected, so the other player hears `_rpc_seat_left`; this is Find another duel on the result screen, on the same connection. A join from a peer in a live room is refused, logged, and answered `dropped` with "Finish or leave your duel first."; every other refusal is only logged.
- Pairing: on every join and every re-queue, while two are waiting, the two who have waited longest go into a new queue room (`DuelRoom.kind` `queue`). Nothing pairs on a timer. `MAX_LIVE_DUELS` in `duel_server.gd` (100, a guess until the journals say what a box carries) caps the rooms in a duel plus the queue rooms still picking. At the cap pairs are held back, everyone waiting hears `queued` with "The server is full. Still looking.", and the once-a-second sweep pairs them as duels end.
- The room: seats in an order from `Crypto`, each seat's first join time kept (`joined_msec`), and each seat's `seat_identity` from its player's greeting. Each player gets `_rpc_matched(seat, pick_seconds, code)`. The code is only for a rejoin, the client never shows it, and a share-code request naming a queue room is refused as "No room has the code …". Both clients open the select screen as the lobby.
- Names: in a queue room's lobby each seat sees the other's stock name ("Player 2") and, once both have locked, its duelist. The deal, the rules, the log and the record use `DuelRoom.shown_name`, the stock names, which the server turns into duelist names as it does for a share-code seat that kept its stock name (a mirror keeps the stock names). No typed name reaches the other player.
- Lock-in: 60 seconds from the pairing (`Net.QUEUE_PICK_MS`, `pick_deadline_msec`). Nothing is ever picked for a player: at the deadline a seat that has not locked is dropped with "You did not lock in a deck in time.", and a seat that has goes back to the front of the queue with "The other player did not lock in a deck. Looking again.".
- Matchup: once both lock, picks are final (the lobby refuses any change, as in a share-code room), each client gets both decks, and the sweep deals 5 seconds later (`Net.QUEUE_BEAT_MS`, `deal_at_msec`) through the same `_start_room` and `room_started` path. The clients do not ask for the deal, and `_rpc_deal_ready` is refused in a queue room. Each client counts "Starting in 5 seconds." ("Game 1 starts in 5 seconds." in a ranked match) from when the unmasked lobby arrived.
- Leaving before the deal: when a player's connection closes during the pick or the matchup, the room closes and the other player goes back to the front of the queue with its first join time (`MatchQueue.requeue`) and `_rpc_queue_state("requeued", "The other player left. Looking again.", waited_ms)`, `waited_ms` counted from that first join. Its client returns to the title still waiting and sets `Net.queue_since` back by `waited_ms`, so the title's count goes on from the first join. Dodging in the matchup costs the dodger its place and nothing else; the journal names the stage of every abandon.
- From the deal on a queue duel is an ordinary room: clocks, away and rejoin (the rejoin file keeps `kind`), concede, and a rematch when both ask. Back to the lobby is refused in a queue room.
- Waiting: the client's title shows "Looking for an opponent" with the time waited, 0:42, and adds "Nobody else is looking right now." after 10 seconds in the casual queue or 90 in the ranked one. Cancel closes the connection and the disconnect takes the peer out of the queue; there is no cancel message. The server drops a peer still waiting after 30 minutes (`Net.QUEUE_MAX_WAIT_MS`) with "No opponent found. Try again later.". A dropped client leaves at once; a connection that stays is closed after 20 seconds like any peer without a room.
- Out of phase: a queued peer's pick, command, deal request, rematch and room request are refused, and a picking peer's command is refused, each logged with the room code.
- Records: a queue duel's record has `mode` `casual`. Casual duels are unrated.
- Leavers: a player on a leaver cooldown (Ranked below) is answered `_rpc_queue_state("dropped", "You can look for a duel again in 4:59.", 299000)` on either queue, the last argument the milliseconds left, and the journal says so. The client keeps the end in `Net.cooldown_until_msec` (ticks; `Net.cooldown_left_ms()` counts it down) before it fails the connection with the line, `leave()` keeps it, and the server taking a later queue join clears it. After a leave that carried no cooldown, `queued` comes with "You left a match recently. Leaving another before a day has passed keeps you out of the queue for 2 minutes." (the next step's minutes). A duel lost `left` in a casual queue room is a leave.
- Wire: client to server `_rpc_queue_join(ticket: Dictionary)`. Server to client `_rpc_queue_state(state: String, reason: String, ms: int)`, `state` one of `queued` (reason "" or the full-server line), `requeued` and `dropped`; `ms` is how long the player has waited since its first join for `queued` and `requeued` (0 on a first join), and for `dropped` how long a leaver cooldown still keeps it out, 0 for any other drop; `_rpc_matched(seat: int, pick_seconds: int, code: String)`; then `_rpc_lobby` and `_rpc_start` as in a share-code room.
- Journal: `queue: peer P joined (N waiting)`, `queue: peer P left, disconnected after S s`, `queue: paired peer A (waited S s) and peer B (waited S s) in room X`, `queue: N waiting, held back at D live duels`, `queue: peer P requeued at the front`, `queue: peer P dropped, did not lock in` or `no opponent after 30 minutes`, `room X: seat N left the finished duel for the queue`, `room X: both locked in after S s, dealing in 5 s`, `room X: pick dealt`, `room X: pick abandoned by seat N in the pick` (or `in the matchup`), `room X: pick timed out, seat N did not lock in`, and the deal line with how long the deal took, `room X: A vs B, seed S, dealt in M ms (D duels live)`.

## Decision clocks

Nothing is ever played for a player. Each decision waits on its player until that player's clock is gone, and then the player has lost the game. `scripts/duel/duel_clock.gd` holds the rules and takes the time as an argument in every call; the room's `DuelHost` owns one (`use_clock`, set only by the server).

- Timer per decision: 30 s; 45 s for a prompt that shows a pile or takes several cards (`context.library`, `batch_max` above 1, `name_card`); 60 s for the Reserve swap at setup. The last 10 s are the warning phase.
- Time bank: 60 s at the deal, plus 10 s at each of the player's own `turn_start`, at most 120 s. It drains only once the decision's timer is gone, and an answer on the bank keeps what is left of it.
- Start: after each update the host arms a clock for every seat that owes a decision (`Referee.prompt_kind_for`). It starts when that client reports its decision panel open (`_rpc_prompt_shown(kind)`, only for the kind the seat owes) or 10 s after the update went out, whichever is first, so a client playing its animations is not charged for them. A modified client can take those 10 s on every decision and no more.
- An answered decision stops its seat's clock. A decision still open keeps running: in the Reserve swap both seats decide at once, each on its own clock, and neither waits on the other. The Discard step asks the active player first and the opponent after, one clock at a time.
- Expiry: a 250 ms `ClockTick` timer in `scenes/server.tscn` calls `DuelHost.tick(now)` for every live room. When a seat's timer and bank are both gone, the host writes the record (reason `timeout`, the other seat wins) and calls `Net.end_room_duel`, which ends the room the way a concession does: `room_ended` first, then `_rpc_duel_ended(winner, "timeout")` to both. When both seats run out, the earlier deadline loses; an exact tie ends with no winner, reason `abandoned`. A seat that runs out while its player is away loses with `left` instead of `timeout`.
- Wire: both clients get `_rpc_clock(seat, left_ms, bank_ms, phase)` for each seat on every change of phase and at least once a second while a clock runs, as time left, never a wall time, so no two clocks need to agree. `phase` is `off`, `run`, `warn` or `bank`. The client counts down from the last one it got.
- The journal gets `room <code>: seat N ran out of time` (`ran out of time while away` for a player who is away) or `both clocks ran out at the same moment, no winner`, then the usual result line.
- Hotseat, vs AI, adventure and the LAN dev path have no clock.

## Reconnects

A server duel survives a dropped connection: a closed game, a crash or a pulled cable. Nothing is ever played for a player who is away, and nothing is replayed on either side when they come back.

- Token: at each deal the server makes a 32-byte token per seat from `Crypto` (64 hex characters), keeps it on the `DuelRoom` and sends it only to that seat, as the last argument of `_rpc_start`. A rematch deals new tokens, and a finished duel forgets them. Tokens never reach a journal line, a record or the other player. They travel inside DTLS (Transport above), and a token is only good from the identity that holds the seat.
- Client file: at the deal the client writes `user://online/rejoin.json` (`RejoinFile`): `server` (the address the duel runs on), `code`, `seat`, `token`, `names` and `decks` (deck ids) per seat, `kind`, `ranked` (a ranked match's seat, so the title knows after a relaunch; false in a file without it, `RejoinFile.ranked(ticket)`), and `expires`, 2:30 on (`RejoinFile.KEEP_SECONDS`), moved on at most every 30 seconds while the server's updates, clocks or a ranked game's result arrive. 2:30 is the 90-second grace plus a minute's margin (`RejoinFile.MARGIN_SECONDS`): up to 30 seconds between renewals, up to 10 for ENet to notice a silent connection, and up to 20 without any message between ranked games. It is deleted at the result, a concession or a return to the lobby. `--dev-scratch=<dir>` moves it to `<dir>/online/rejoin.json`, so two dev clients on one machine keep one each.
- Detection: the server sets each peer's ENet timeout (`ENetPacketPeer.set_timeout(32, 5000, 10000)`) as it greets it, so a silent peer is dropped within 10 seconds instead of ENet's default 30. A client sets the same on its server connection.
- Away: a seat whose connection drops mid-duel is marked away (`DuelRoom.away_since`) instead of ending the duel. The other player gets `_rpc_seat_away(seat, 90000)`: their log says "X lost connection.", X's plate reads "Disconnected 1:12" and the waiting panel "X has 1:12 to come back.", both counting down the grace or X's clock, whichever runs out first. The away seat's clock keeps running, so a decision it owes still runs out; that loss reads `left`. The record counts each drop in `disconnects`.
- Grace: 90 seconds (`Net.REJOIN_GRACE_MS`). A seat still away after that loses the duel with `left`, even with time on its clock. The journal says `seat N did not come back`.
- Both away: both clocks stop, since nobody is kept waiting, and the room waits 90 seconds. Nobody back by then ends the duel with no winner, `abandoned`, and closes the room. The first player back resumes with both clocks running from where they stopped, and the other seat's grace runs on from where it stood.
- Rejoin: the client connects, passes the greeting and sends `_rpc_rejoin(code, token)` instead of a room request. The server re-seats it and sends `_rpc_resume(seat, code, deck0, deck1, deck_name0, deck_name1, name0, name1, color_seed)`, the deal's fields, so the client loads the duel scene; then `_rpc_seat_away` if the other seat is still away, one catch-up update from `Referee.catch_up(seat)` (the seat's current view and prompt and this turn's log lines from its `turn_start`, without animation data, the shape `Referee.replay` gives a resumed adventure duel), and both clocks. The other player gets `_rpc_seat_back(seat)` and their log says "X is back." The record counts each return in `reconnects`.
- Refusals: a wrong code or a room that is gone ("That duel is no longer on the server. It may have restarted."), a duel that is over ("That duel has ended."), a token that fits no seat, and a good token from another identity ("That seat belongs to another copy of the game.") come back as `_rpc_rejoin_failed(reason)`, and the client deletes its file. A token for a seat the server still counts as connected (its old connection not yet timed out) comes back as `_rpc_room_failed`, and the client tries again.
- Client during the duel: when the connection drops and the rejoin file is good, the table shows "Connection lost" and "You lose if you are not back in 1:05." with Concede, which asks "Concede the duel?" with Concede and Keep trying, and tries again every 3 seconds until the time is gone: the server's grace, or the seat's own clock when that runs out first.
- Concede while away (`Net.give_up()`, the Concede button on the reconnect overlay and on the title): while the connection holds it is an ordinary concession. Cut off, the client deletes its rejoin file at once and opens a short connection of its own, over DTLS to the pinned certificate, whose hello also carries `give_up: {code, token}`. The screens leave the main connection straight after, and this one is not part of it. The server answers the hello with a nonce like any other and reads the give-up only after a good proof; it checks the token in constant time, the identity must be the seat's, and the seat must be away in a running duel. It ends the duel through `_end_room(room, other seat, "concede")`, so the record is written first and the other player hears "X conceded." at once. In a ranked match it concedes the whole match instead (`_leave_match`, Ranked below), during a game or between games, and the match ends `concede_match`. The server answers on the greeting, `{"gave_up": true}` or `{"refused": reason}`, and never lets that connection in. A seat whose old connection the server has not yet seen drop is answered with `"again": true`, and the client tries again every 3 seconds. A wrong token, a wrong room, another identity or a finished duel is refused with the same reasons a rejoin gets. With the server out of reach, or no answer within 20 seconds, the duel ends as before, once the seat's time runs out, with `left`.
- Client on relaunch: the title reads the rejoin file. Inside its expiry it shows "Your duel against X is still running." ("Your match against X…" for a ranked seat) with Rejoin and Concede, which asks "Concede the duel?" (or "Concede the match?") inline first. Past its expiry, or refused, the file goes and the title says the duel ended. The file can outlive the seat by up to a minute past the grace, and by longer when the duel ended another way while the player was away (the other player conceded, or the seat's clock ran out); a Rejoin then gets "That duel has ended." and the file goes. With both seats away the room waits 90 seconds from the second drop, which can outlast the first player's file.
- Server restart: every live duel ends and nothing is recovered. A rejoin is then refused with "That duel is no longer on the server. It may have restarted." and no record is written for those duels.
- Journal: `seat N lost connection`, `both seats are away`, `seat N is back (peer P)`, `seat N gave up while away (peer P)`, `seat N did not come back`, `both seats stayed away, no winner`, and every refused rejoin or give-up with its reason.

## Ranked

A ranked match is best of 3 on the same two decks, rated once when it is decided. It is reached only through the ranked queue, never through a share code, and nothing is ever played for a player.

- Queue: `_rpc_queue_join({"identity": <id>, "mode": "ranked"})` (`Net.find_ranked()`; `Net.find_duel()` is always the casual queue) joins a second `MatchQueue`, `Net.ranked_queue`, with `rated` set. Each entry carries its identity's mu. A player accepts an opponent within `3 + 3 × (seconds waited / 30)` mu, and anyone after 90 seconds; two pair when either one's window holds the gap, the oldest player taking the oldest opponent it accepts. The once-a-second sweep pairs again as the windows widen. The same two identities are not paired twice in a row until both have waited 60 seconds, and an identity is never paired with itself. A ranked join needs an identity ("Ranked play needs this copy of the game's key." otherwise, which a greeted client never sees). From the pairing on the room is a queue room as in Find a duel (lock-in, masked lobby, matchup beat, re-queue into the ranked queue at the front), with `DuelRoom.ranked` set and `best_of` 3.
- Series: the first deal locks the picks for the match (`series_locked`; any pick after it is refused and logged) and draws `match_id`, 16 hex characters from `Crypto`. Each game is dealt through the same `Net._deal` with a fresh seed, and the engine's setup Reserve swap opens for both seats on its 60-second clock. Game 1's opener is the engine's rule; in games 2 and 3 the loser of the game before opens (`DuelEngine.set_first_player`, the record's `first.reason` is `forced`). Seats and colours stay fixed. Before each deal, and before a rejoin's resume, each seat gets `_rpc_series(best_of, game, wins)`.
- Between games: a game that does not decide the match puts the room in `BETWEEN`. After the result (`_rpc_duel_ended` for a concession, or the update carrying `game_over` for a rules finish) both seats get `_rpc_game_over(game, wins, next_in_s)`, `wins` games per seat and `next_in_s` 20. The server deals the next game once both seats have sent `_rpc_next_ready()` (`Net.next_game_ready()`), or when 20 seconds are up (`Net.NEXT_GAME_MS`, `DuelRoom.next_deal_msec`, the sweep). Rematch, back to the lobby, a concession and a pick are refused between games.
- What ends the match: a second game won; a game lost `left` or `timeout`, or ended `abandoned`, whatever the score; or a player conceding the match. Concede game (`_rpc_concede()`, `Net.concede()`) loses the current game only. Concede match (`_rpc_leave_match()`, `Net.leave_match()`) loses the whole match as a concession, which is not a leave: the match ends `concede_match` (`_rpc_match_over`'s `reason`, the deciding record's `match.reason`), while the game it ends on reads `concede`. During a game it concedes that game (`_rpc_duel_ended(winner, "concede")` first), and between games the match ends on the next game, set up with a fresh seed and never dealt, whose record says it was conceded on turn 0 (only `_rpc_match_over` goes out then). A give-up from a seat cut off in a ranked match (Reconnects above; the reconnect card's and the title's Concede match) is a Concede match, between games too.
- Result: the match's result is counted before either player hears anything: the game's record takes `match` and, when rated, each seat's `rating`, and the rating is applied once through `RatingsStore.apply`. Then each seat gets `_rpc_duel_ended` when the game ended outside the rules, and `_rpc_match_over(payload)`: `winner` (seat, -1 for none), `wins` [2], `reason` (what ended the match: a result reason, or `concede_match`), `rated`, `shown_before` [2] and `shown_after` [2] (both seats' shown ratings), `provisional` [2] (after the match), and this seat's own `rating_before` and `rating_after` (`{"mu", "sigma"}`). An unrated match shows the ratings as they stand. The client keeps the payload in `Net.last_match`, the last `_rpc_game_over` in `Net.last_game_over` (`game`, `wins`, `next_in_s`, and `at_msec`, the ticks it arrived at) and the last `_rpc_duel_ended` in `Net.last_duel_ended` (`winner`, `reason`), so a scene built after the message can still show it. Only the next deal or resume and a new queue join clear them; `Net.leave()` and a dropped connection keep them, so a disconnect in the same frame as a result still shows it. The room is then `OVER`: Find another duel or ranked match leaves it; rematch and back to the lobby stay refused.
- Away between games: a seat whose connection drops between games stays away with its seat, identity and token; a ranked match keeps one token per seat from its first deal to its end, and each `_rpc_start` repeats it. A rejoin between games is answered `_rpc_room_failed("The next game of your match is being dealt. Trying again.")`, so the client tries again. The next game is dealt with that seat away: its Reserve clock runs, its grace runs on from the drop, and a clock or grace run out loses `left`, which ends the match. With both away both clocks wait, and 90 seconds of both away ends the match with no winner, unrated. The client keeps its rejoin file through a ranked match until `_rpc_match_over`, so a closed game can come back into the next game.
- Rating (`scripts/server/rating.gd`, `Rating`): openskill's two-player Plackett-Luce update, ported (MIT licence, noted in the file): mu 25, sigma 25/3, beta 25/6, kappa 0.0001, tau 25/300, the tau step first. `tests/fixtures/rating_golden.json`, written by `tools/rating_golden.py` from the openskill 6.2.0 package, holds the port to 1e-9. A player sees `max(0, round(40 × (mu − 3 × sigma)))` (`Rating.shown`), "Provisional" while sigma is above 6. A first match won shows 138. Each player gets `_rpc_rating(shown, provisional, mu, sigma)` right after the greeting.
- Files, in the data directory beside the records: `ratings.json` (`RatingsStore`: identity id to `mu`, `sigma`, `games` (rated matches), `wins`, `last_played` in Unix seconds) and `conduct.json` (`Conduct`: identity id to the Unix times of its current run of leaves, nothing else), each written whole to a temporary file and renamed over the old. The server refuses to start on either file when it cannot read it, rather than reset everyone.
- Leaver cooldown, on both queues, by identity: a leave is a duel lost `left` in a queue room (casual or ranked; away past the grace, or the clock ran out while away) or leaving a ranked matchup once both decks are shown (a dodge). A concession, Concede match, a `timeout`, leaving before the lock-in and a double drop are not. The first leave is a warning; the second keeps the identity out of both queues for 2 minutes, then 5, 15, 30 and 60 (the cap), counted from that leave. A day without a leave clears the run. Share-code rooms count nothing.
- Recovery: the records are the source of truth. `RatingsStore.rebuild(records)` starts empty and replays every ranked server record whose `match` has a winner, in the order given (the day files in name order, their lines in order), then `save()` writes it. No tool calls it yet: to rebuild, stop the service, move `ratings.json` aside, and run a script that reads the day files into `MatchRecord`s and calls those two.
- Journal: `queue: peer P joined ranked, mu M (N waiting)`, `queue: ranked pair peer A (mu M, waited S s) and peer B (mu M, waited S s) in room X, window W mu` (or `window open`), `room X: game N to seat S (reason), series A-B`, `room X: both ready, dealing game N` or `dealing game N`, `room X: match to seat S, A-B (reason); seat 1 mu … sigma … -> … …, shown A -> B; seat 2 …` (or `, unrated`), `room X: seat N left the match`, `room X: seat N (<short id>) left the duel, a leave: a warning` (or `out of the queues for 2:00`, and `dodged the ranked matchup`), `queue: peer P refused, <short id> on a leaver cooldown, 4:59 left`. Identities appear as their first 12 characters only.

## What the server checks

No RPC reaches the server from a peer that has not proved its key in the greeting (Identity above). The seat always comes from the sender's connection, never from the message, and a rejoin or give-up also from the identity that took the seat. Anything but waiting from a peer in the queue, a pick after the deal or after both seats have locked, a deal request before both seats have locked or in a queue room, a queue join from a peer in a live room, a prompt notice outside a duel or that is not a string of at most 64 characters, a command outside a duel or for the other seat, a rematch, lobby or concede request in the wrong phase, a rematch in a ranked room, a pick in a locked ranked match, a next-game request outside a ranked match between games, a Leave match outside a ranked match and a queue ticket naming an unknown mode are dropped and logged with the room code. Every field of a pick or a command is type-checked (a command has only `player`, `type`, `card` and `value`; a value is nothing, a flag, an int, a string of at most 64 characters, or at most 128 card uids) and a malformed one is dropped. Names are cut to 20 characters and lose `[`, `]` and control characters on the server and on the receiving client. The Referee's own check that a command is the deciding seat's and one of its options stays behind all of that. The greeting is capped at 1 KB and a client refuses an update that unpacks past 4 MB; ENet's own packet size limit is not exposed to scripts, so a single oversized RPC is only stopped by those checks after it has been decoded.

## Match records

Every finished game becomes one record (`scripts/duel/match_record.gd`), one JSON object per line. The server signs and files the online ones (`scripts/server/match_log.gd`).

- Fields: `v` (2; the loader takes 1 and 2, and a version 1 record writes back as version 1, so its signature still checks), `id` (16 random hex characters), `match_id` (16 hex, shared by every game of a ranked match, the record's own `id` otherwise; version 2), `game` (1 to 3 in a ranked match, 1 otherwise; version 2), `origin` (`server` or `client`), `protocol`, `catalog` (the full catalog hash), `build` (`application/config/version`, which the project does not set yet), `mode` (`code` for a share-code room, `casual` for a Find a duel room, `ranked` for a ranked match; `vs_ai`, `hotseat`, `adventure` offline), `started` (Unix seconds, UTC, at the deal), `seed`, `color_seed`, `first` (`seat` and `reason`, `double_power`, `chance` or `forced`, from the engine's `setup` event), `rules` (`lives` per seat, `seal_point`, `second_life`, and `guest` and `boss_power` card ids per seat), `seats` (per seat `identity`, the 64-character id its player proved in the greeting on a server record and empty on a client one, `name`, `deck` as the catalog file stem, `ai` profile or empty, and `list`, the deck inline, only when it is not a catalog file as it stands, as in an adventure run), `commands` (`Referee.history` in wire form, each with `at`, ms since the deal), `result` (`winner` 0, 1 or -1, `reason`, `turns`, `duration_ms`, `points`), `disconnects` and `reconnects` (per seat, how often its connection dropped and how often it came back; a seat away when its game was dealt counts one), `dev`, `sig`. On the game that decides a ranked match only: `match` (`winner` seat or -1, `wins` per seat, `reason`, what ended the match: a result reason, or `concede_match` for a match conceded as a whole, whose game `result.reason` still reads `concede`; the loader takes `concede_match` in `match.reason` only, and a build before it refuses such a record) and, when it was rated, `seats[].rating` (`before` and `after`, each `mu` and `sigma`).
- `MatchRecord.setup_referee()` sets the duel up again, and `Referee.replay(record.commands)` plays it to the same table.
- The loader (`MatchRecord.from_dict`, with `problem_of` for the reason) is strict. It checks every field's type, refuses unknown keys and versions, takes at most 5,000 commands, caps strings, allows only `a-z0-9_` in deck and card ids, and turns JSON's whole-number floats back into ints. A new field needs a new `v`.
- A record holds no addresses, ports, peer ids or keys. Its names are the ones the rules used: cleaned typed names or duelist titles. The identity ids are hashes of public keys, and each player's copy carries both seats' ids.
- Order: the server writes the record before either player hears the result. A rules finish is written inside the command that ended the game, before the update carrying `game_over` goes out. A concession, a seat that did not come back or a duel both players left is written in the `room_ended` handler, before `_rpc_duel_ended`. A clock that ran out is written by the host before it ends the room. The first result written stands.
- Delivery: after the result each seat gets the signed record in one message (`_rpc_record`), capped at 1 MB on both ends, and keeps the last 200 in `user://matches/online.jsonl`. The server refuses to send a record while its room is in a duel, and no update during a game carries the seed or the command list. Deal seeds come from `Crypto`, not from the generator behind room codes and seat colours, so the seeds players see in records say nothing about the next deal. They are 53 bits wide, too many to find from an opening hand, and still read back exactly from JSON.
- Data directory: `--data-dir=<path>` (default `user://`) holds `secret.key` and `matches/YYYY-MM-DD.jsonl`, one file per UTC day of writing. Each record is appended with open, append, flush, close. The journal gets `record <id> written` or `record <id> failed: <reason>` and nothing else about a record. A failed write never holds up the result; the players still get it and the record.
- Signature: on first start the server makes `secret.key`, 32 random bytes from `Crypto`. It refuses to start if it cannot write the key, or if the key there is not 32 bytes. `sig` is HMAC-SHA256 under that key over `MatchRecord.canonical()`: the record as JSON with sorted keys, no whitespace, whole numbers as ints, and `sig` left out. `MatchLog.verify()` recomputes it and compares in constant time. The key is never logged or sent. Without it no earlier signature can be checked, so back it up with the records.
- File modes: the engine sets none. `install.sh` makes the data directory (`/var/lib/eidolarch` unless given) owned by the service user with mode 0700, and the unit runs with `UMask=0077`, so the key and the day files are 0600.
- Retention: `--keep-days=N` (default 90) deletes day files older than N days at start and once a day after.
- Client records: vs AI, hotseat and adventure duels write a record with `origin: "client"` and an empty `sig` into `user://matches/local.jsonl` (last 200) when the rules end the duel or the player concedes. It is the player's own history, made on their machine, so nothing uses it for rating or shared stats. `--dev-scratch=<dir>` sends a dev run's client records to `<dir>/matches/`.
- Copy them down with `scp root@<ip>:/var/lib/eidolarch/matches/*.jsonl .`.

## Reading the records

`tools/match_stats.gd` reads records and prints per-deck and per-matchup win rates, how the first player does, and how duels ended. It prints them as text tables in matchlab's layout (`MatchStats`, `tests/sim/match_stats.gd`).

Pull the day files into a folder of their own first:

```
scp root@<ip>:/var/lib/eidolarch/matches/*.jsonl C:/records/
```

Then, from the repo root:

```
& $godot --headless --path zenith -s tools/match_stats.gd -- --in=C:/records
& $godot --headless --path zenith -s tools/match_stats.gd -- --in=C:/records --since=2026-09-20 --until=2026-09-26 --cards --json=C:/records/week.json
& $godot --headless --path zenith -s tools/match_stats.gd -- --in=user://matches/local.jsonl --origin=client --mode=vs_ai,hotseat,adventure
```

- `--in=<file or folder>`: one JSON-lines file, or a folder whose every `*.jsonl` is read. Default `user://matches`, the client's own folder. Use forward slashes or `res://` and `user://` paths.
- `--since=YYYY-MM-DD`, `--until=YYYY-MM-DD`: UTC days of the deal, both inclusive.
- `--mode=`: a comma list of `ranked`, `casual`, `code`, `lan`, `vs_ai`, `hotseat`, `adventure`. Default `ranked,casual,code`, so AI and hotseat games never mix into player numbers unless named. Share-code rooms are `code`, Find a duel rooms `casual` and ranked matches `ranked`, each game of a match its own record.
- `--origin=server|client|all`: default `server`. `client` or `all` takes unsigned records, which a player's machine wrote about its own offline games.
- `--secret=<path>`: the server's `secret.key`, or the folder holding it. Each server record is checked with `MatchLog.verify`, and one whose signature the key does not reproduce is skipped and counted. A client record has no signature to check. The flag refuses a folder with no key, because `MatchLog.open` would make a fresh one, and it leaves an empty `matches/` folder beside the key if none was there. Anyone holding the key can sign records, so keep the copy off shared drives. Records pulled straight from the server with `scp` need no check. The flag is for copies that passed through other hands, such as a player's `online.jsonl`.
- `--catalog=all|<hash prefix>`: default `all`, one block per catalog hash. A prefix keeps one block.
- `--cards`: the card pass (below).
- `--tsv=<path>`: one row per counted duel. `--json=<path>`: the whole report with the flags. Unknown flags stop the run, as in matchlab.

The run starts with how many lines it read and how many records it skipped, and why. It always skips `dev` records and any line `MatchRecord.from_dict` refuses (`refused: <reason>`). Filtered records are listed too, for example `origin client`, `mode vs_ai` or `before --since`.

Records group by `catalog` hash, oldest first, because a card or deck data change starts a new balance period. Each block says how many records it holds and their dates. The block for the catalog this build runs is marked `this build`. In each block:

- DECKS: duels, win rate with its 95% Wilson range, wins and losses by reason, duels with no winner, and mean turns, decisions and minutes. Mirror duels are left out, as matchlab never plays them, and the block says how many there were.
- MATCHUPS: the row deck's win rate against the column deck, counted from both seats.
- FIRST PLAYER: how often the seat that went first won, over duels with a winner and mirrors included, then each deck going first and going second.
- ENDINGS: the share of each result reason, the turn of each concession in buckets (1-2, 3-5, 6+), and disconnects and reconnects per 100 duels.
- RANKED, when the block holds ranked records: counted by match, from the record that decided each one. Each deck's match win rate with its range (mirror matches left out), how many matches were won 2-0, 2-1 or ended early (a `left`, `timeout` or a match conceded at 1-0 or 1-1), and how often the game 1 winner took the match. A match ended `concede_match` counts by its score exactly as one ended `concede`. The games of a match still count one by one in the blocks above, the game a match was conceded in as a `concede`. A match conceded between games ends on a game that was never dealt, which counts there as a concession on turn 0.
- CARDS, with `--cards`: each duel is rebuilt with `MatchRecord.setup_referee` and `Referee.replay`, and the tool reads the card behind every attack, defense, use, counter, placement and Relic command. For each card it shows times played, duels played in, and the win rate of those duels. A duel counts once for each seat that played the card, so a card both seats run can count twice in one duel. Only records on this build's catalog are replayed, since the uids would point at other cards under other data. The block says how many it passed over, and names any record that would not replay.

What the numbers mean at alpha sizes: the Wilson range is the part to read. At 20 duels a deck at 50% spans about 30-70%, and at 100 duels about 40-60%. A difference between two decks means something only when their ranges stop overlapping. The first weeks will mostly show how many games were played and how they ended. A card's win rate follows the duels it was played in, and cards played while ahead look strong for that reason alone. Read it as a pointer to a card to look at, not a verdict on it.

## Size

Measured with `tools/load_probe.gd`: about 365 KB and 6 ms of CPU per command per live duel, 3.5 to 4.7 KB on the wire per update. The headless process idles near 100 MB. A 512 MB, 1 vCore box carries dozens of duels at once. Around 1,000 concurrent players (500 duels, roughly 165 commands a second) it would take one full core and about 1 MB/s; delta updates instead of whole views (the view build is 90% of the cost) and a second core cover that.

## Presence

Each client tells the other what its player is doing right now (`scripts/net/presence_state.gd`): the pointer as a point on the table plane in shared table coordinates (`TableLayout.to_shared`), the uid of a public table card under it, the slot index of a hovered hand card, and which pile, public card or panel is open (a Discard, Out or Relic pile by seat, an inspected public card by uid, the log, or "choosing" for any tray). It never carries a card id, a title, or the uid of anything in a hand, a Reserve or a Life Deck; a tray, including a Life Deck search, is only "choosing". It goes out only when something changed, at most 20 times a second, on its own `unreliable_ordered` channel (`Net.PRESENCE_CHANNEL`), so commands and updates never wait on it. The server relays it only to the other seat of the sender's started room, and a LAN host takes it only from its seated joiner during a duel; both run `PresenceState.sanitise` first (allowed keys and types only, point clamped to the table, slots and uids range-checked, strings capped and matched to a fixed list) and drop more than 40 messages a second from one peer. Presence never reaches a `DuelHost` or the `Referee`. The receiving client sanitises again and drops any uid its own view cannot see. Hotseat, vs AI and adventure send and draw nothing.

## Install on the box

Any Linux VPS with a public IPv4 works. Google Cloud's free e2-micro (`us-central1`, Debian 12, 1 GB egress a month) or a RackNerd yearly plan (512 MB is enough) are the cheap options. Open UDP on the port (7777 by default): on Google Cloud a firewall rule for the instance's network tag with `udp:7777`; on a plain VPS the install script adds a ufw rule if ufw is present.

```
scp build/server/eidolarch_server.x86_64 tools/server/install.sh root@<ip>:
ssh root@<ip> bash install.sh 7777 /var/lib/eidolarch <ip>
```

The script puts the binary in `/opt/eidolarch`, runs it as a system user under systemd (`eidolarch.service`, restarts on crash and on boot) with `--data-dir=/var/lib/eidolarch` (the second argument) and `--host-name=<ip>` (the third, default `eidolarch`, which no client dialling an address accepts), waits up to 20 seconds for the first start to make the DTLS certificate, prints the service status, and then where the certificate is (`/var/lib/eidolarch/dtls.crt`, made for `<ip>`). Copy it into the project as `data/net/duel_server.crt` before exporting a client (`deploy.ps1` does). Re-run it with a new binary to update; the certificate stays.

- Logs: `journalctl -u eidolarch -f` shows rooms opening and closing with the reason, duels starting with their seed, clocks that ran out, results, `record <id> written`, and refused messages.
- Stop or start: `systemctl stop eidolarch`, `systemctl start eidolarch`.

Then put `<ip>:7777` into `zenith/net/duel_server` in `project.godot`, check `data/net/duel_server.crt` is the box's certificate, and export the Windows client (`--export-release "Windows Desktop" build/windows/eidolarch.exe`, same GDScript-only editor) to send to a friend. The Windows preset embeds the pack and stamps the exe with `icon.ico` (rendered from `icon.svg` with `magick -background none -density 512 icon.svg -define icon:auto-resize=256,128,64,48,32,16 icon.ico`) and the version fields set in `export_presets.cfg`.

## Update in one step

```
powershell -File zenith\tools\server\deploy.ps1
```

exports the server with the GDScript-only editor, uploads it with `scp`, re-runs `install.sh` over `ssh` with the host part of `-Server` as the host name (which restarts the service), prints the last journal lines, and copies the box's `dtls.crt` down to `zenith/data/net/duel_server.crt`, the file the project setting pins. It says whether the certificate changed; when it did, export the Windows client again, since a client built before it is refused by the new certificate. `-SkipExport` uploads the last export, `-Server root@host` and `-Port N` change the target, `-DataDir <path>` the data directory and `-HostName <name>` the certificate's name. It needs key-based SSH to root, so it never asks for a password. Every duel in progress ends when the service restarts; there is no drain yet. Export and deploy from the same commit as the clients you hand out, or they are refused at the greeting, and deploy before exporting the clients.
